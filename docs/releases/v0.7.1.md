# cargo-libc 0.7.1

Published 2026-11-21 UTC through Trusted Publishing from exact release commit
`15d27d50d7be9b5d7e2822e47b493147fb382c3a` (annotated tag `v0.7.1`).

## Changes

- Update `kernel-abi-tools`, `linux-abi-scan` and `linux-targets` from 0.3 to
  0.6.1 together. The three crates share one data model, so they move as a set.
  Their published `linux-abi-scan` and `linux-targets` sources and the kernel
  ABI data are byte-identical between 0.3.3 and 0.6.1. `kernel-abi-tools` 0.6.1
  only makes its embedded-table decoder return an error instead of panicking on
  a malformed row; the bundled tables are valid, so results are unchanged.
- No cargo-libc behavior change: commands, options, exit statuses, JSON/TSV
  output, generated Cargo configuration, provider descriptors and cache formats
  are the same as 0.7.0. Packaged source differs only by fuzz-only entry points
  compiled under `--cfg fuzzing` (never in installed binaries) and a README badge.

This is a patch under the [version policy](https://github.com/rustcommons/cargo-libc/blob/main/docs/RELEASING.md#choosing-a-version):
a compatible dependency update that preserves every documented contract.

## Upgrade

Install all five helpers together:

```sh
cargo install cargo-libc --version 0.7.1 --locked
```

`libc-abi-tools` stays 0.6.0. Provider-cache identity covers that producer
version, the glibc ABI inputs and host GCC details, none of which change, so
providers prepared by 0.7.0 are reused with the same host tools.
Generated `cargo libc env` files name the cargo-libc version only in their
comment header; regenerating them is optional. Rust 1.90, native-tool floors,
glibc ABI/source inputs (0.1.2/0.1.1), clock linking and the system `libgcc_s`
unwinder policy are unchanged. Cargo-libc 0.7.0 remains immutable.

## Validation and limits

Rust 1.90 source tests (105 library and ten process cases), fmt, Clippy and
rustdoc passed, along with hosted Linux/Windows/MSRV checks. The registry-only
candidate run built against crates.io alone and passed providers (2.17, 2.28),
C/CMake, Cargo commands and both plain-Cargo formats, host/target separation,
streams (direct, Docker, Podman), malformed-scan bounds, the package audit and a
clean unpacked locked install of all five helpers. The official archive matches
the crates.io API and index checksum, the tag's source and the audited delta
from 0.7.0; docs.rs built it, and a fresh registry installation passed the
installed-helper checks. Exact runs and identities are in the
[release record](https://github.com/rustcommons/cargo-libc/blob/main/docs/RELEASE-0.7.1.md).

Existing limits remain: tier 1 inspection and tier 2 simulation are not
old-system qualification, and real old-system (tier 3) evidence is still
deferred. Modern-host container checks share the host kernel. Target libgcc
matching remains a bounded explicit two-file check.

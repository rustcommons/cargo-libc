# cargo-libc 0.6.0

Release candidate, prepared 2026-11-07. Publication is pending.

## Changes

- Reject duplicate `--sysroot`, `--gcc-runtime`, `--cc`, `--ld`, `--artifact`
  and inspect `--max-glibc`, including identical repeated values. Previously
  these six options silently used their last value. This completes the duplicate
  checks already present for other cargo-libc-owned value options.
- Report invalid arguments with status **1**, a stderr diagnostic such as
  `duplicate --max-glibc`, and no stdout report, before provider preparation,
  compiler execution or ELF inspection.
- Add permanent parser/process regressions, an installed-tool CLI gate and a
  repository instruction requiring the same contract for future value options.

## Upgrade

Install with `cargo install cargo-libc --version 0.6.0 --locked` after publication.
Scripts that append an override must instead choose one value before invocation.
For example, replace `inspect app --max-glibc 2.17 --max-glibc 2.22` with
`inspect app --max-glibc 2.22`. Repeating an identical value is also an error.
The stricter accepted-CLI contract requires a minor version under repository policy.

Compiler/linker defaults, repeated switches, existing selection conflicts and
the `--` forwarding/positional boundaries retain their behavior. Provider
subcommand parsing remains delegated to libc-abi-tools. There are no dependency,
MSRV/native-tool, provider-cache identity, clock-linking, system unwinder or
libgcc-checker changes. In particular, this does not remove `libgcc_s.so.1` or
ship the separate LLVM research.

## Validation and limits

Implementation source `fdf487fa6c13d99eb7acaa479e031528aa502910`, merged as
`219027a17cb9e35d82b0d6e1d56862bd68f001a5`, passed Windows Rust 1.99 tests
(100 library and one portable process test), formatting, Clippy and rustdoc
with warnings denied. Linux/WSL Rust 1.90 passed 105 library tests and ten
process tests. A real-CLI regression failed before the fix and passed afterward.
Exact-head and merged documentation CI passed. Candidate package/install and
postpublication checks remain pending; see the linked record for their results.

No new real-container, old-OS/tier 3, musl/static-host or LLVM interoperability
qualification is claimed. Existing runtime/dependency-closure and prebuilt legal
limits remain. A libgcc static match is still not a runtime safety certificate.

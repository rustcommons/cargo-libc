# cargo-libc 0.5.0 candidate

Prepared 2026-11-03; **not published**. This candidate adds
an explicit static libgcc interface check; it does not replace an unwinder or
select a runtime. Producer 0.5.0 availability is verified and only the root
producer is adopted from the real registry. Bounded candidate registry/package/
clean-install and native Windows CLI qualification passed; final excluded-evidence
review, normal merge and publication remain pending. Cargo-libc
0.4.0 remains the current published version.

## Changes

- Add `inspect APP --target-libgcc FILE`, including opt-in JSON schema version 1.
  Read both explicitly supplied files without loading or executing either one;
  never discover/substitute the host runtime. Matching is internal Cargo ELF
  parsing plus the companion crate's pure std-only byte-hash API.
- Check non-weak version requirements owned by `libgcc_s.so.1` independently of
  dynsym binding, then exact owner-attributed function symbol/version pairs and
  externally visible/hash-reachable definitions. Weak symbols and weak version
  nodes are separate. Wholly versionless runtime fallback is unresolved; complete
  versioned metadata can prove a missing mandatory node even when optional symbol
  enumeration fails. Incomplete enumeration is never treated as empty inventory.
- Report input SHA256/length/ELF identity, separate node/symbol completion, scoped
  mismatches/exclusions and the supplied runtime's own NEEDED/search/version
  metadata. Optional parser errors preserve the primary artifact's valid report.
  No target-libgcc parser or GCC matching runs when the option is absent.

## Upgrade

The new command option, opt-in report and status contract use minor 0.5.0 under
repository policy. Without the option, ordinary inspect text/JSON/exit behavior
is preserved. With it: 0 means match plus independent checks pass; 2 means known
mismatch or a separate glibc/scan failure; 3 means unresolved without an independent
failure; 1 remains CLI/primary-artifact/reporting error. A GCC match plus candidate
GLIBC_2.34 above `--max-glibc 2.22` retains GCC `match` but returns 2.

Only libc-abi-tools now requires published 0.5.0 for the pure byte-hash API.
Its real registry checksum is
`c598bccdec99a399cc8ea639c69ffd59a58dd3dc7904ea5cc586afd01dcea469`,
with clean producer VCS `bc7fcb35ea86409a2a9f543b8d25b65ed321cf47`; archive/API
checksum, non-yanked state and public hash API were independently verified. Kernel/scanner/targets stay locked
0.3.3 and their direct floors remain unchanged; glibc-abilists 0.1.2 and
provider-sources 0.1.1/checksums stay unchanged. Rust 1.90 and native-tool floors,
clocks, system unwinder, linker state and host/target selection are unchanged.
No path/git patches or source replacements are permitted in release inputs.

The root producer version is part of provider-cache identity. Moving 0.4.x to
0.5.0 can prepare a fresh provider even though the API addition is pure; existing
version-keyed providers are not silently reused. There is no promise of imported
or automatic offline migration. Source preparation needs host GCC/recorded inputs;
container preparation also uses host startup/tool inputs and needs its selected
engine/image. This is distinct from container execution userland.

`2c70e47954f328e55950d738d5a9295de7c44d67` passed 102 library tests, nine process
tests and 36 GNU static native fixtures, Rust 1.90 build/docs and pinned 1.99
fmt/Clippy. Legacy inspect text/JSON matched actual released 0.4.0 in the named
fixture. The final source packet has 150 member hashes, 16,028,453 bytes, SHA256
`0b7cd40fbf354141bde0d10205f53358685be26b25dd4e2e7880dab6fecc7ef8`.
This is disposable-source-patch evidence, **not registry/package/install
qualification**. Its contents-only package audit used `--no-verify`; it does not
establish an unpatched release package build. The later real-registry qualification below is separate from that source run.

Actual tested registry/package candidate
`c5f41485af05bd311c15f567a6bd9310a3154237` passed unpatched Rust 1.90 tests
(102 library, nine process, zero doctests), docs, verified package and clean-home
unpacked locked installation. The clean candidate archive has **28 files,
84,781 bytes**, SHA256
`5ac6373f445fceb8b0ffd0549cd9f33ff61de51f70d296ac4949f3dcc028a441`.
All five installed helpers, provider 2.17/C/CMake/host separation/local simulation,
target C++ refusal and thirteen capability cases passed. The first installed
stream attempt correctly refused a leaked docs-only RUSTDOCFLAGS override with
exit 1; after clearing only the driver environment, streams, installed 36 GNU static
checker cases, actual released 0.4.0 ordinary text/JSON comparison and docs passed.
This is explicitly **composite resumed evidence**, not one monolithic all-green
run; no source/package/install change was needed for the resume.

[Portable CI41684307122](https://github.com/rustcommons/cargo-libc/actions/runs/41684307122)
passed Linux/Windows Rust 1.99 tests/fmt/Clippy/docs and the Rust 1.90 all-target check
at exact `c5f41485`; [local-mode docs CI41684311480](https://github.com/rustcommons/cargo-libc/actions/runs/41684311480)
passed separately. Actual Windows x86_64 MSVC/Rust 1.99 CLI controls returned
match 0/missing 2/wholly-versionless unresolved 3 and verified artifact/runtime full
SHA256s against transported GNU ELF fixtures. They did not execute Linux payloads.
The native/Windows packet is 14,930,341 bytes, 228 verified member hashes,SHA256
`461de6aff75d0009e11cd5d038346db123012aa70acc9067d485eb9c25894322`.
The [candidate release record](https://github.com/rustcommons/cargo-libc/blob/main/docs/RELEASE-0.5.0.md)
retains full identities, failure/resume and scope. Later excluded evidence docs
preserve these package inputs; a later VCS hash is not this tested archive hash.

Supported metadata is x86-64 ELF64 little-endian Linux/System V; target runtime
must be ET_DYN with SONAME `libgcc_s.so.1`. Primary read limit 256 MiB, target 64 MiB;
optional parser limits 262,144 symbols, 65,536 metadata records, 1,024 program headers,
16 MiB accumulated strings; comparison 32,768 combined symbol entries; dynamic
relocation budget 262,144 across REL/RELA/PLT. Both input buffers are retained during
comparison, and hashing/parser/report working memory is additional. **These are
read/work bounds, not a total-process memory cap.** No EOF count guessing or
truncated-inventory success is allowed.

LLD was unavailable in the source qualification environment; no LLD or Windows
candidate pass is claimed there. The conditional LLD fixture remains applicable when that linker is available;
the separately passing portable CI does not invent an LLD result. Static fixtures are linked and inspected, never executed.
A match is structural interface evidence only: no loader-selected file, runtime
implementation authenticity, transitive/plugin/CPU/kernel closure, C++ support,
GCC/LLVM cross-DSO safety, real musl/static host or old-OS/tier3 qualification is
established. Existing prebuilt legal and unwinder limitations remain unchanged.

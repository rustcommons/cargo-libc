# cargo-libc 0.7.0

Published 2026-11-08 UTC from exact release commit
`6317117a2bea3644fa0cba11df5ac61448fd7408`.

## Changes

- Require published `libc-abi-tools 0.6.0` to repair provider-cache publication.
  Normal preparations use distinct staging directories; complete immutable
  generations are published through atomic selection files. Forced preparation
  retains paths already returned to builds, explicit descriptors and saved settings.
- New automatic selection uses the current generation. Its actual paths enter
  Cargo's existing target fingerprint, causing a rebuild before subsequent reuse.
  Invalid current-selection metadata refuses without silently choosing a legacy
  entry. Legacy directory discovery and the six-field v1 descriptor remain supported.
- Add permanent installed-tool regression coverage for managed reuse/refresh,
  retained file hashes, saved plain-Cargo settings and explicit Rust/C/CMake inputs.
  Keep published-install checks separate from the older 0.6.0 baseline.

This is a conservative minor under the project's provider/cache contract policy:
selection, physical layout and validation semantics change through the delegated
producer. It is not a new compiler floor or unwinder change. Rust implementation
source is unchanged from released cargo-libc 0.6.0; the actual dependency minimum
and real registry lock enforce adoption. No new public clock or unwind option.

## Upgrade

Install all five helpers together:

```sh
cargo install cargo-libc --version 0.7.0 --locked
```

Cargo-libc 0.6.0 remains immutable and uses producer 0.5.0. Publishing the
producer alone did not update that Cargo installation; install this consumer
release explicitly. Existing duplicate-option refusals remain.

The producer version participates in provider-cache identity. The first build
after upgrading may prepare a new provider. Old/imported version-keyed entries
are not an automatic offline migration. Source mode needs host GCC/binutils and
startup files; container preparation additionally needs its engine/image and
possibly archives/network. External GCC startup files are independently managed.

Use paths returned by preparation or `provider path`; do not reconstruct physical
cache directories. A saved plain-Cargo config or explicit descriptor stays bound
to its original generation. Regenerate `cargo libc env` settings or choose the
new returned descriptor to switch. New paths may rebuild Cargo outputs even
when the provider input hash is unchanged.

Retained generations consume disk. Stop builds and other cache operations before
`provider remove` or manual deletion. Preparation's retention does not protect
against removal, manual edits or external compiler updates. Older binaries do
not coordinate the new layout. No automatic GC, reader lease, authenticated
delivery, crash-durable transaction or distributed-filesystem guarantee is added.

The kernel/scanner/targets locks remain 0.3.3 and existing minima are preserved;
their source/data are unchanged through workspace 0.6.0. Glibc ABI/source inputs
remain 0.1.2/0.1.1 with identical checksums. Rust 1.90, native-tool floors,
host/target separation, clock linking and the system `libgcc_s` unwinder policy
remain unchanged. LLVM archive research is deferred and unassigned.

## Validation and limits

The merged adoption was qualified with real registry dependencies, a clean
unpacked locked installation and all five helpers. It covered managed build,
reuse, forced selection, fingerprint rebuild/reuse, five retained file hashes,
old saved settings and explicit Rust/C/CMake inputs. A real previously published
0.6.0 installation supplied the legacy-provider upgrade control. Stream,
capability and duplicate-option checks passed. Initial harness/setup failures
and corrected resumes remain in the dated evidence; none is counted as a pass.

The exact 0.7.0 package inputs passed Rust 1.90 source tests (105 library and ten
process cases), package/payload and registry-checksum audits, and a clean unpacked
locked install with all five helpers. The fresh-home smoke driver first failed
because it fetched the C fixture after an offline generation check. A test-only
ordering fix passed against the same installed bytes; original failure and resume
remain separate. Generation16, capability13, singleton options, native C/CMake,
streams and 36 static libgcc cases passed, along with hosted Linux/Windows/MSRV
checks. Exact refs, archive/proof hashes and limits are in the release record.

The official 28-file archive matches crates.io API/index checksum and clean
release-source VCS; annotated tag and docs.rs README/API are verified. Fresh
actual registry installations passed native generation/C/CMake/capability/helper
checks. Hosted installed run 42526522128 also passed Docker/Podman run and test
with exact stdout, stdin, spaced environment values and exit status preservation.
The local direct-runner harness inherited an unrelated installer target directory;
its test-only isolation fix passed against unchanged installed binaries. Original
failure and corrected resume are retained separately in the release record.

Named modern-host/container checks do not establish real old-system, arbitrary
container/Python/shared-library or musl/static-host compatibility. Existing tier 3,
prebuilt legal and whole-process unwinder limitations remain. A static inspect
pass is not runtime certification; target libgcc matching remains a bounded
explicit two-file check, with dependency closure and runtime behavior unchecked.

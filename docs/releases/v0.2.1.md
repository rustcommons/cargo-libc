# cargo-libc 0.2.1

Closing a stdout reader no longer panics or hides later command failures.

Original crates.io publication: 2026-10-31 (UTC). Package `cargo-libc` 0.2.1
is available and non-yanked, checked 2026-11-02. Source tag `v0.2.1`:
`767c16aef0e49c37018b3907be480363dfdb9175`.
These notes were reconstructed on 2026-11-02; their later GitHub publication date
is documentation backfill, not the original software release date. They were not
present at the historical tag and do not modify its package.

## Changes

- Ignore owned stdout broken-pipe errors only at write/flush boundaries, while
  preserving scan findings, child exit codes, later failures and other I/O errors.
- Forward test/program arguments after Cargo's second `--`; published 0.2.0
  rejected these forms. Exercise plain-Cargo too-new-symbol refusal.
- Include container-runner SLES 12 SP5 userland integration and current provider/
  shared-library help. This is modern-kernel tier 2, not an actual old SLES host.

## Upgrade

Install `cargo-libc` 0.2.1 with `--locked`. The direct provider minimum becomes
`libc-abi-tools` 0.3.2 and the packaged four-tool graph uses registry 0.3.2;
glibc inputs remain 0.1.0. Keep failure-status handling in pipelines: suppressing
a broken pipe does not mean the operation succeeded. Wrapper diagnostics are
separated from program stdout more fully by 0.2.2.

## Validation and limits

The detailed release record documents registry-only qualification and clean

# cargo-libc 0.2.2

Run/test stdout preserves program data, and container stdin, environment and statuses stay intact.

Original crates.io publication: 2026-11-01 (UTC). Package `cargo-libc` 0.2.2
is available and non-yanked, checked 2026-11-02. Source tag `v0.2.2`:
`b87563c6be6faf89ac26055f88fb520991125b8b`.
These notes were reconstructed on 2026-11-02; their later GitHub publication date
is documentation backfill, not the original software release date. They were not
present at the historical tag and do not modify its package.

## Changes

- Send owned Cargo-wrapper diagnostics and dry-run command descriptions to stderr;
  preserve report/configuration stdout and program JSON pipelines.
- Make final error reporting fallible across all five executables without losing
  error/refusal/child statuses when stderr is closed or full.
- Adopt scanner/kernel 0.3.3 fixes: bounded malformed scanning accepts valid large
  ELF tables, and Docker/Podman execution preserves stdin, environment and statuses.

## Upgrade

Install `cargo-libc` 0.2.2 with `--locked`. Scanner/kernel minima become 0.3.3;
all four tools in the package lock resolve to 0.3.3, with glibc inputs still 0.1.0.
The provider version changes its cache key: an initial build may prepare fresh
providers; old version-keyed entries are not silently reused. Source preparation
needs host GCC; container preparation may need network/image access. No offline
cache migration/import guarantee is provided.

## Validation and limits

Registry run 41268879926 and published-install run 41269812853 passed at the
exact refs in the detailed record. Evidence includes large real Cargo/rustc ELFs,
malformed inputs, C/CMake, both plain-Cargo formats and Docker/Podman run/test
JSON/stdin/env/exit-7 checks. Actual old-system tier 3 remains deferred; modern
containers do not substitute for it.

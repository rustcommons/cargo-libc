# cargo-libc 0.2.0

The Rust library exposes documented executable entry points rather than internal implementation helpers.

Original crates.io publication: 2026-10-14 (UTC). Package `cargo-libc` 0.2.0
is available and non-yanked, checked 2026-11-02. Source tag `v0.2.0`:
`3b283b044dca36d0e5b446d99874e0c46ea8c402`.
These notes were reconstructed on 2026-11-02; their later GitHub publication date
is documentation backfill, not the original software release date. They were not
present at the historical tag and do not modify its package.

## Changes

- Restrict the public Rust surface to the five executables' entry points and
  their required public types/modules; internal selection/configuration helpers
  become crate-private.
- Add API documentation and doc checks. The intended consumer interface remains
  the Cargo command and installed helpers, not a stable general-purpose Rust API.
- No new runtime/linker behavior is introduced by the visibility/documentation change.

## Upgrade

CLI users keep the same workflow and install `cargo-libc` 0.2.0 with `--locked`.
Rust callers using formerly public internals must migrate: these are no longer
external APIs. Use `libc-abi-tools` for provider operations or `linux-abi-scan`
for scanning in library consumers. Rust 1.90 and existing native prerequisites
are unchanged.

## Validation and limits

Tag/source diff inspection confirms visibility and documentation changes;
registry/archive/source identity was rechecked for this backfill. The original
publication acknowledgement is retained in commit bd221157; no exact-release
saved CI artifact set was recovered/re-audited here. Do not transfer later 0.2.1
plain-Cargo or container corrections backwards to this release. Tier 3 remains
unqualified.

The [history audit](https://github.com/rustcommons/cargo-libc/blob/main/docs/releases/HISTORY.md) records original registry dates,
archive checksums and bounded historical evidence gaps. No checks were fabricated
